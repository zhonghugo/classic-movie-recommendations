# 经典电影推荐 · 44 部归档

一个每日自动化任务连续 44 天生成的经典电影推荐卡片合集。每期只推一部**公认的经典**（评分高、口碑好），含无剧透剧情梗概、亮点、推荐理由、批评意见与版本提醒，选片严格避开此前所有已推荐影片。

**在线浏览**：<https://zhonghugo.github.io/classic-movie-recommendations/>

每张卡片都是**单文件、零外链、零依赖**的 HTML——GitHub Pages 直接打开，或下载到本地双击，都不需要联网补任何资源。

## 里面有什么

| | |
|---|---|
| 期数 | 44 期，无重复 |
| 影片年份 | 1931（《城市之光》）– 2019（《寄生虫》） |
| 推荐日期 | 2026-10-06 → 2026-11-22 |
| 单期内容 | 剧情梗概（安全区）· 亮点 · 为什么值得一看 · 批评 · 版本指引 · 思考题 |
| 硬性规则 | 不剧透；评分与奖项逐期现查；口径差异（快照浮动、小样本、老片回溯分）明写；批评不替影片辩护 |

索引页支持按片名／外文名／年份／关键词**搜索**，可按期号、年份、豆瓣分**排序**，还能「随机抽一部」。数据内嵌在 `index.html` 里，因此本地用 `file://` 打开也能正常搜索和跳转。

## 目录结构

```
.
├── index.html          # 索引页（由 build_index.py 生成，勿手改）
├── build_index.py      # 索引生成器，仅依赖 Python 标准库
├── publish.py          # 发布入口：推送 + 校验 + 清理本地（每日自动化调用）
├── movies.json         # 44 条元数据，唯一数据源
├── README.md
├── .nojekyll           # 让 GitHub Pages 跳过 Jekyll
└── outputs/            # 仓库内归档的全部卡片 HTML
    └── 电影推荐-*.html
```

> 仓库只包含上述内容。生成端的工作区台账（`.workbuddy/`）属于内部记录，不在此仓库中。

## 每日自动发布（生成即推送，本地不留存）

每日自动化任务生成新卡片后，**不再保留本地副本**：卡片只是临时落在工作区 `outputs/`，发布成功后即移入废纸篓。仓库是唯一真源。

一键发布（自动化每期调用一次）：

```bash
python3 publish.py \
  --card "/abs/path/outputs/电影推荐-片名.html" \
  --meta '{"n":45,"date":"2026-11-23","title_cn":"片名","title_en":"Original Title","year":1957,"scores":"豆瓣 9.4 · IMDb 9.0","note":"评分口径与奖项备注"}'
```

`publish.py` 内部严格按顺序执行：

1. 把卡片放进本仓库 `outputs/`，在 `movies.json` 追加一条元数据
2. 运行 `build_index.py` 重建索引并校验（期号连续、引用文件存在）
3. `git commit` + `git push`
4. **校验远端 `HEAD` 与本地一致**（推送确实生效）
5. 只有第 4 步通过，才把本地临时卡片移入 **废纸篓**（可恢复）

> **顺序铁律**：推送失败、校验不过或任何异常，脚本都会报错退出且**绝不删除本地卡片**。本地那份是唯一还没进远端的副本，不能先删。
> 删除用系统的 `trash` 命令；若系统没有 `trash`，脚本会拒绝删除并提示手动处理，不会用 `rm`。

演练（在 `/tmp` 的仓库副本里跑完整本地流程，**不推送、不删除、真实仓库零改动**）：

```bash
python3 publish.py --card ... --meta ... --dry-run
```

`build_index.py` 会校验「期号必须连续」和「引用的卡片文件必须真实存在」，`publish.py` 额外拦「期号跳号／重复」，任一不满足都会直接报错，避免索引静悄悄少一部。

### movies.json 字段

| 字段 | 说明 |
|---|---|
| `n` | 期号，从 1 连续递增 |
| `date` | 推荐日期，`YYYY-MM-DD` |
| `title_cn` / `title_en` | 中文片名 / 原片名 |
| `year` | 影片上映年份 |
| `scores` | 一行评分摘要，如 `豆瓣 9.2 · IMDb 8.5 · RT 90%` |
| `note` | 评分口径与奖项备注（索引页截断显示） |
| `file` | `outputs/` 下的文件名 |

## 关于数据

- 评分来自豆瓣、IMDb、Rotten Tomatoes、Metacritic 等公开页面，**逐期现查**，不同快照之间的浮动已在卡片中注明，不挑一个数字假装权威。
- 有多部影片是「单线压线达标」（如豆瓣未过线但 IMDb 达标），按选片规则的「或」字口径收录，并在卡片里写明，不包装成破例。
- 部分老片的 Metacritic 为回溯分、样本极小，卡片中一律标注口径，不硬凑。
- 所有推荐文案为原创整理；影片海报、剧照等未包含在内，避免版权与外链依赖。
